# Documentation

## Principles
- Lead with what it is and who it is for.
- Show a working quick-start in under 5 commands.
- Prefer examples over prose; every example must be runnable.
- Document the "why" for non-obvious decisions.

## README skeleton
1. Title + one-line purpose
2. Quick start
3. Usage / examples
4. Configuration
5. Troubleshooting
6. Contributing / license

Verify commands against the actual code before publishing.
